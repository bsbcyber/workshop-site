WHAT IS GITHUB ACTIONS?

Learn five words, then walk the UI with your partner.

Five words

Workflow = the recipe file (YAML). Job = one named box of work. Step = one line inside a job. Action = a reusable published step (uses: …). Run = one execution of that recipe (the Actions tab).

  1. In your new repo, open the Actions tab. Allow workflows if GitHub asks.
  2. Open the Security Lab run (or use Run workflow). This is one automated execution of the recipe.
  3. In a second tab, open .github/workflows/security-lab.yml. Find on: (when it runs) and jobs: (the work boxes).
  4. Back on the run page, click one red job (example: Semgrep). Expand one step and the LEARN block.
  5. In the YAML, find a line that starts with uses: — that is an Action (a packaged step someone published).
Why this matters

GitHub can re-run these checks on every push. You automate “did we break a security rule?” without installing scanners on your laptop. Today’s scanners (Semgrep, OSV, Gitleaks, zizmor) are just jobs in this workflow.

You are not writing a workflow yet — only naming the pieces so the red checks make sense.

Finding vs tool failure

A finding completed the scan and reported a rule/advisory. A tool failure is an image pull, missing binary, or empty report. Only findings count for this lab.

SAST · SEMGREP · PYTHON · GATE G1

Read LEARN blocks, then do guided Commit A.

  1. Sample app is Python. With your partner, open LEARN for SAST-001 and SAST-002. Run all five READ prompts on each.
  2. List what you found: eval and exec in src/profile.py (also note shell concat + hard-coded password for later).
  3. Commit A (Must — facilitator order): on your repo, replace preview_expression so it does not call eval, and preview_formula so it does not call exec. Use the projector snippet (or the block below).
  4. Update tests/test_profile.py for allow + reject. Commit. Semgrep should drop 4 → 2.
_ALLOWED = {"2 + 3": 5, "1 + 1": 2, "2 * 4": 8}

def preview_expression(expression):
    key = expression.strip()
    if key not in _ALLOWED:
        raise ValueError("not allowed")
    return _ALLOWED[key]

# Same allowlist idea for preview_formula — do not call exec().
  1. Gate G1: eval and exec findings are gone.
  2. Should — Commit B: remove/rewrite ping_host (no os.popen concat) and clear LEGACY_API_PASSWORD in src/settings.py.

You are not ranking severity yet — follow the guided order. Edit in the GitHub web editor; no local Semgrep install.

SCA · OSV-SCANNER · GATE G2

Update PyYAML and Flask from today’s advisories.

  1. With your partner, open the OSV LEARN / FROM THIS RUN section. Run READ prompts (tool, package, advisory link, one-sentence risk).
  2. Confirm requirements.txt pins PyYAML==5.3.1 and Flask==1.0.
  3. Open each advisory link. Write down the fixed version it names — do not guess from memory.
  4. On your repo, update both pins in requirements.txt. Commit and re-run. Use the facilitator’s verified pins if you get stuck.
  5. Gate G2 (Must): OSV green for both packages; unit tests still pass. Must is complete.
Teaching point

SCA answers “is this version already known-bad?” even if you did not write the library. Always read today’s advisory — fixed versions drift.

WORKFLOW · ZIZMOR · SHOULD

Harden the inert workflow fixture.

  1. Open lab-fixtures/insecure-workflow.yml only. Keep it outside .github/workflows/.
  2. Replace permissions: write-all with least privilege (e.g. contents: read).
  3. Replace pull_request_target with workflow_dispatch (dangerous trigger).
  4. Replace the two unpinned uses: lines using the LEARN REPLACE WITH block (pinned checkout + setup-python SHAs from security-lab.yml — swapping the fixture’s setup-node is fine; this file never runs).
  5. Add with: persist-credentials: false on checkout.
  6. Remove or rewrite the curl … | bash training smell (do not run it).
  7. Commit and confirm zizmor is green.

Never move this fixture under .github/workflows/ — it must not execute.
