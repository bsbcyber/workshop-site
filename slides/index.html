HOW A CHANGE GETS PUBLISHED

What happens between editing and publishing?

The most common confusion is assuming a save, a commit, a push, and a deployment are the same thing.

LIVE URL
SavedThe file on your computer changed.
CommittedGit recorded a snapshot in local history.
PushedYour commit was sent to GitHub.
DeployedThe automated publish finished; verify the URL.

STEP 4 · RECOVERY10 / UNDO SAFELY

HOW TO UNDO A CHANGE

Check what changed before you undo anything.

Use the least destructive action that matches the state of your file.

SituationCommandWhat it does
Unstage one filegit restore --staged src/data/profile.jsRemoves it from the next commit; keeps your edits in the file.
Discard edits to one filegit restore src/data/profile.jsReplaces that file with the last committed version. Your edits to it are lost.
See the last commitsgit log --oneline -5Inspect history before choosing a recovery step.
Confused or conflict showngit statusRead the state. Stop and ask before running more commands.
Do not use these as a guess:git reset --hardgit push --forceThey can discard work or overwrite shared history.
IF YOU’RE UNSURE, STOP AND CHECK STATUSSTATUS FIRST · ASK IF UNSURE

STEP 10 · DEBUG16 / TROUBLESHOOTING

FIND THE STEP THAT FAILED

Find the failing step before changing anything.

Start with the symptom, inspect evidence, and change one thing at a time.

“not a git repository”Run pwd / inspect the folder. Move to the project root that contains package.json; use git init only for a downloaded ZIP without Git.
Push asks for password / auth failedUse browser sign-in, or a classic PAT with repo scope as the password — not the GitHub account password. See student guide Step 3.
Push rejectedRun git status and git remote -v. Stop and inspect why the remote differs; don't force push or blindly overwrite history.
Build failed in ActionsOpen the failed job log and find the first useful error. Reproduce locally with npm run build; fix the referenced file and push again.
First Actions run failedConfirm Settings → Pages → Source = GitHub Actions, then open the failed run and choose Re-run all jobs.
Site URL returns 404Check Settings → Pages, confirm the latest workflow succeeded, and use the full project URL including the repository path.
HTML loads, styles/assets don'tCheck the asset URL in browser dev tools and the Astro base path. A leading slash can point at the domain root rather than the project subpath.
Latest change isn't visibleConfirm the PR was merged to main, the newest Actions run succeeded, the URL is correct, then hard refresh.
Useful diagnostic order: git status → reproduce locally → read the error message → make the smallest fix → rerun the check.
Ask the roomBefore changing anything: what is the exact error text or screenshot you would show a helper?
