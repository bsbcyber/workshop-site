# Student Field Guide — Workshop 1

**Start here online:** [Open the six-mission student field guide](https://skyeshanohan.github.io/workshopsite/student-guide/)

This guide is the printable/markdown companion. The online guide is the primary in-class experience: it has the mission route, real screenshots from official GitHub and VS Code docs, an interactive Git state lab, copyable commands, and choices for common blockers.

## Mission

Build a portfolio website, manage one meaningful change in Git, review it on GitHub, and publish the result. You do not need to know everything before beginning. Follow the route until each checkpoint works.

## Bring

- A laptop and internet access
- A GitHub account you can sign into
- Visual Studio Code and Git
- Access to GitHub Copilot if available (there is a non-AI path)

## The route

1. **Access:** open GitHub and VS Code.
2. **Claim:** create a repository for the starter you will edit.
3. **Explore:** open the correct project folder and run the local site.
4. **Shape:** choose a portfolio direction and make one focused content/design change.
5. **Review:** create an issue, branch, commit, push, and pull request. Inspect the diff before merging.
6. **Launch:** check Actions, open the real published URL, and test it.

## If you are behind

Open the field guide and choose a recovery option:
- **Starting fresh:** return to Mission 1 and use the starter.
- **Local site works:** skip setup and continue to the Git workflow.
- **Push failed:** run `git status` and `git remote -v`; do not force-push.
- **Deploy failed:** open the latest Actions run, expand the failed step, and read the first actionable error.

## Copilot prompt pattern

Give context, describe one outcome, state constraints, and ask how to verify the result. Ask it to explain before editing. Inspect every changed file and use the diff and local build to verify it.

## Safety

Do not paste passwords, API tokens, private keys, or confidential information into prompts or source files. Only publish personal details you are comfortable making public. Treat AI-generated code as a proposed change that you remain responsible for reviewing.

## Completion evidence

- [ ] The project runs locally.
- [ ] A focused change is visible in the diff and recorded in a descriptive commit.
- [ ] The issue/branch/pull-request path was completed or demonstrated using the class checkpoint.
- [ ] The latest deployment succeeded and the real public URL opens.
- [ ] You can explain one Git concept and one Copilot change you reviewed.
