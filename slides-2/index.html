Secure development with GitHub Actions.

  • Python sample app · Must / Should / Stretch
  • Case study on your Workshop 1 resume site

Partner up. Own repo. Must / Should / Stretch.

  • Must — scout + Commit A (eval+exec) + PyYAML & Flask
  • Should — all 4 SAST + 3 secrets + workflow
  • Stretch — PR + resume case study + peer-review
04

Partner talk = READ prompts, not “prioritize.”

  • Tool + rule id?
  • File + line? Open it — match?
  • One READ MORE link — risk in one sentence?
  • What does THIS IS HOW TO FIX THIS show?
05

Do not deploy this lab. Ever.

Intentionally vulnerable. Synthetic secrets only. A clean scan is evidence for triage — not proof the software is secure.

06

Use this template → your public repo.

Open bsbcyber/secure-dev-lab. Create under your account. Work in the GitHub web editor — scanners run in Actions.

github.com/bsbcyber/secure-dev-lab ↗

07

Actions → Security Lab. Red scanners are expected.

Unit tests should pass. Semgrep, OSV, Gitleaks, and zizmor should fail with findings — not empty logs or pull errors.

08

Five words: workflow · job · step · Action · run.

  • Workflow — the recipe file (YAML) that says when + what
  • Job — one named box of work (Semgrep, OSV, …)
  • Step — one line inside a job
  • Action — a reusable step others published (uses: …)
  • Run — one execution of that recipe (what you see in the Actions tab)
09

Do this now — on your repo.

  • Actions → open the Security Lab run
  • Code → .github/workflows/security-lab.yml — find on: and jobs:
  • Back to the run → click one red job
  • Expand one step + the LEARN block
  • In the YAML, find a uses: line — that is an Action

Automation idea: every push can re-run these checks — no local scanner installs.

10

Gate G0: a finding finished the scan. A failure never started one.

With your partner, run READ prompts 1–3 on one failed job. Setup errors get a re-run — not a code guess.

11

Scout with your partner — then wait for the room.

  • Semgrep — 4 Python rules
  • OSV — PyYAML + Flask
  • Gitleaks — 3 fixtures
  • zizmor — unpinned, artipacked, dangerous-triggers
12

Four scanners, four questions.

  • Semgrep — does this Python pattern look dangerous?
  • OSV-Scanner — is a dependency version known-bad?
  • Gitleaks — does this look like a secret?
  • zizmor — is this workflow configured unsafely?
13

Semgrep on Python: start with eval and exec.

Each LEARN block has THIS IS HOW TO FIX THIS with paste-ready code. Commit A (Must): follow that block (or the next slide). Optional: Copilot Chat — “Apply this LEARN fix exactly.”

14

Commit A — type this (no eval).

_ALLOWED = {"2 + 3": 5, "1 + 1": 2, "2 * 4": 8}

def preview_expression(expression):
    key = expression.strip()
    if key not in _ALLOWED:
        raise ValueError("not allowed")
    return _ALLOWED[key]

Do the same idea for preview_formula (no exec). Update tests for allow + reject. Commit on your own repo.

15

Gate G1: eval and exec findings are gone.

Should = also fix shell concat + hard-coded password. Stuck? Paste the REPLACE WITH block from LEARN — or ask Copilot Chat to apply that LEARN fix exactly.

16

SCA: OSV flags PyYAML and Flask.

Open the advisory links from the run. Write the fixed version. Update requirements.txt — don’t guess.

17

Gate G2: OSV green for both — Must complete.

If versions get messy, use the facilitator’s verified pins for today.

18

Should: clear all three synthetic secrets.

Token file, fake AWS key, fake GitHub PAT. Logs stay redacted. Clearing one is not enough.

19

Should: harden the inert workflow fixture.

Paste the LEARN REPLACE WITH block (pins checkout + setup-python). Drop pull_request_target. Least privilege. Add persist-credentials: false.

20

Stretch: open a PR, then peer-review your partner.

Branch → PR → checks. Walk one LEARN block using the READ prompts.

21

Stretch: case study on your Workshop 1 resume site.

Name the tools, at least two findings, what you changed, and a link to your lab. Do not deploy the lab.

22

Behind → finish Must. Ahead → Should, then Stretch.

Don’t leave early. Help your partner with READ prompts before helping another pair.

23

Exit: explain two findings with READ prompts. Show the resume link.

A clean scan helps you triage. It does not mean “secure forever.”
